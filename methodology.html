$ methodology

what the colored dot next to each headline means

Every headline gets a small dot next to it. That dot is generated by a small open-weight language model running locally in the site's build pipeline (fittingly, since this whole site is about local open-weight models). Here is exactly what it does, with no hidden steps.

What it is not

This is not a fact-check. The model never browses the web, never verifies a claim, and only ever sees a headline, its source type, and its social score, never the article body. Treat the dot as a rough signal about how the headline is framed and where it came from, not a verdict on whether it's true.

Disclaimer: the label is the output of an automated language model, not an editorial judgment by Twin Kites LLC about any person, publisher, or organization. A red label means the headline's phrasing and corroboration looked weak to a small model given only a title and a vote count, it is not an assertion that the linked content, its author, or its publisher is inaccurate, untrustworthy, or acting in bad faith. See the content disclaimer for more.

It's also deliberately not a 0-100 score, and the model is not asked to weigh multiple factors and pick a label in one pass either. Both were tried and both failed the same way: a 1.5-billion-parameter model can't reliably do multi-step numeric reasoning zero-shot. Asked for a 0-100 score, it clustered on round numbers (0, 20, 50, 85, 95, 100) rather than actually discriminating, fake precision, not a measurement. Asked to "apply these rules using this number," it fabricated reasons like "corroboration is 20+" for items whose real count was 1 or 2, it wasn't doing the comparison, just completing the rule text it had just been shown.

So the label is a hybrid, split by what each part can actually do:

  • Corroboration (how many people have seen and not disputed it) is a number we already have, so it's bucketed in plain Python: low under 5, medium 5-19, high 20+. Official release feeds (GitHub releases, project blogs) aren't voted on at all, so they get their own official tier rather than being penalized for a missing number.
  • Framing (does the title read as sober/descriptive or hype/clickbait?) is the one thing asked of the model, a short text-style judgment, not arithmetic.

The two combine deterministically:

  • hype framing → red, regardless of corroboration
  • sober framing, low corroboration → red
  • sober framing, medium corroboration → yellow
  • sober framing, high corroboration or an official release feed → green

The legend

green: sober framing, well-corroborated or an official release yellow: sober framing, moderate corroboration red: hype-framed, or sober but barely corroborated

The model

Qwen2.5-1.5B-Instruct, quantized to Q4_K_M GGUF, run via llama-cpp-python on CPU during the scheduled GitHub Action. It never leaves the build machine and nothing is sent to a third-party API.

The exact prompt

This is the only question the model is asked (see scripts/evaluate_truthiness.py), with {'{title}'} filled in per item. Everything else on this page (the corroboration bucketing, the combining rules) runs as plain Python, not model output:

Title: {title}

Does this headline's phrasing read as sober and descriptive, or as hype
and clickbait (absolute claims, exclamation points, vague superlatives,
fear/awe-mongering)?

Respond with ONLY a JSON object, no other text:
{"framing": "sober" | "hype", "reason": "<under 8 words>"}

Known limitations

A 1.5-billion-parameter model is small. It can miss sarcasm or get confused by unusual titles when judging framing. Scoring is best-effort: if the model fails to load or produces unparsable output for an item, that item simply shows no dot rather than a guessed label. There is no calibration against ground truth, this is a heuristic, not a validated classifier. The reason shown in the hover tooltip is assembled from the model's own framing judgment plus the exact corroboration numbers, not the model's text verbatim, since the model never sees or reasons about the combined outcome.
